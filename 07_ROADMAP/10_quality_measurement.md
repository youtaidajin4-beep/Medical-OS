# 品質計測（音声認識・SOAP）— 管理画面と、AIが読む口

2026-10-10 導入。診察が終わるたびに、音声認識とSOAPの品質を1行ずつ DB に積み、月ごとに見られるようにする。
**診療の画面とは別**（`/admin/quality`、診療のメニューにリンクなし）。

目的は2つ。(1) 先生に「直りました」と言う前に、数字で動きを確かめる。(2) 構成（モデル・語彙・プロンプト）を変えたとき、
どの月に何が動いたかを、AIが自分で読んで学べるようにする。

## どこを見るか

| 見たいもの | 場所 |
|---|---|
| 画面（月ごとの推移・診察ごと） | `/admin/quality`（ADMIN ロール、または環境変数 `QUALITY_ADMIN_EMAILS` のメール） |
| 数字だけのCSV | 画面の「CSV」／ `GET /api/v1/quality/export.csv?month=2026-10`（要ログイン・管理者） |
| AIが読む表（月ごと・診察ごと） | `cd apps/backend && DATABASE_URL=... npx ts-node scripts/quality-report.ts 6 --visits 2026-10` |
| 元データ | テーブル `quality_measurements`（診察1件につき1行。`consultation_id` で一意） |
| 構成が変わった時点 | 画面の下部「構成が変わった時点」。各行の `config`（モデル名・コミット・辞書の語数）の差分 |

**数字が動いたときの手順**：`quality-report.ts` で月ごとの表を出す → 動いた月を `--visits` で診察ごとに見る →
`config` の `commit` と `git log` を突き合わせる → 診察の行を開いて、落ちた用語・落ちた事実を見る。

## 指標の定義

正解データの無い本番では、**基準との比**しか測れない。絶対値ではなく、構成を変えた前後の**動き**で読む。
割合は診察の合算（診察ごとの割合の平均ではない）。診察が少ない月は±数ポイント動く。

| 指標 | 何を測るか | 基準 | 元の列 |
|---|---|---|---|
| 発話の再現率 | 基準の文字2連のうち、診察中の文字起こしに残った割合。一致率は逆向き（仮説のうち基準にもある割合） | 録音全体の文字起こし（`OPENAI_WHISPER_MODEL`、既定 gpt-4o-transcribe-diarize） | `utterance_recall` / `utterance_precision` / `ref_chars` |
| 医療用語の回収率 | 基準に出た辞書の語（病名・症状・所見・薬・検査・画像・処置）のうち、診察中の文字起こしにも出た割合。補正後（SOAPの材料）と補正前（音声認識そのまま）を並べる | 同上 | `term_ref_count` / `term_hit_count`（補正後）/ `term_raw_hit_count`（補正前）/ `missed_terms` |
| SOAPの転記率 | 会話に出た診療上の事実のうち、SOAPに書かれた割合 | LLM判定（3段） | `fact_count` / `fact_hit_count` / `missed_facts` |
| 根拠のない記載 | SOAPの記載のうち、会話に根拠がないもの。0であるべき | LLM判定（3段目） | `unsupported_count` / `unsupported_claims` |
| 先生の修正 | SOAP・診療録・文字起こしを先生が直した回数（1診察あたり） | 修正履歴 | `revision_history`（保存せず読み出し時に集計） |

- 基準の長さが40字未満、用語が3語未満、事実が3件未満の診察は、割合を出さない（`null`。0%とは別）。
- 月の境界は日本時間。
- 会話・SOAPの本文は保存しない。残るのは数字と、落ちた用語・事実の短い断片だけ（診察と同じDB内。診察を消すと一緒に消える）。

### いつ測るか（パイプライン）

- **SOAPの転記率**：SOAPができた直後に裏で（`AiPipelineService` → `QualityService.measureSoap`）。待たない。
- **発話の再現率・用語**：診察中の文字から作ったSOAPのあと、録音が届いてから録音全体を文字起こしする
  既存の取りこぼし確認（`verifyLiveCoverage`、既に走っていた処理）の結果を使う。**追加の文字起こし費用は無い。**
  録音の保持期間（既定24時間）を過ぎると基準は作れない。
- どちらも失敗しても診療は止めない。失敗は `stt_error` / `soap_error` に残り、画面に「一部未計測」と出る。
- 計測を止めるには `QUALITY_MEASUREMENT=off`。

## SOAP転記率の判定（LLM）— 較正の結果（2026-10-10）

判定は `modules/quality/soap-coverage-judge.ts`（v3）。**最初の版は使えなかった**：会話とSOAPを一度に見せて事実を挙げさせると、
SOAPにある事実しか挙がらず、人が的を付けた症例（転記65%）を100%と判定し、SOAPを半分に削っても100%のままだった。
そこで3段に分けた：①会話だけから事実を挙げる（SOAPは見せない）②その事実がSOAPにあるか ③SOAPの記載に会話の根拠があるか
（SOAPの文面からの引用だけを採る）。

`eval/soap-corpus`（実診療3症例）で、同じSOAPを測り直した：

| 確認 | 結果 |
|---|---|
| 同じSOAP（Zoom+GPT）を2回判定 | 症例①：49%と48%（事実の数は37と33。分母は揺れるが割合は安定） |
| 人が的を付けた転記率との差 | 症例①：人65%・判定49%。**判定のほうが低く出る**（事実を細かく数えるため）。**eval の 74%（Zoom+GPT）とは物差しが違うので、比べない** |
| SOAPを半分に削る | 49% → 25%。ちゃんと下がる |
| 捏造を4件足す（血圧・HbA1c・心音異常なし・処方） | 症例①で2件、症例②で3件を拾う（取りこぼしあり） |
| 足していない原文での誤検出 | 症例①で2〜4件、症例②で4〜5件。1〜2件の誤検出は見込む |
| 費用 | 約3円/診察（gpt-4o、3回呼び出し） |

読み方：**転記率は月の動きで読む**。「根拠なし」は絶対数ではなく、月ごとの増減とその中身（診察の行を開く）で読む。
基準線（目標値）は、最初の1か月の実測を取ってから置く。eval の Zoom+GPT 74% は、人が的を付けた別の物差し。

## 残っている限界

- 基準（録音全体の文字起こし）は正解ではない。2人の声が重なる区間では、基準も落とす。
- 用語の回収率は、**辞書にある語**だけを数える。辞書に無い薬名が両方で崩れていれば、数字に出ない。
- 診察中の文字起こしは gpt-4o-mini-transcribe、基準は gpt-4o-transcribe-diarize。差が「モデルの差」なのか「区切り方の差」なのかは分けていない。
- 実診察の音声での各エンジンの比較（OpenAI新モデル・医療向けの外部エンジン）は、まだ測っていない。この計測が溜まってから、同じ音声で比べる。
- 診察が月に数件のうちは、1か月の数字は±10ポイント動いてもおかしくない。

## 運用

- 反映：`prisma migrate deploy` はコンテナ起動時（`apps/backend/Dockerfile` の CMD）に走る。マイグレーションは
  `prisma/migrations/20261010000000_quality_measurements`（テーブル追加のみ。既存テーブルは触らない）。
- 管理画面を見る人：ユーザーの `role` を `ADMIN` にするか、Railway の環境変数 `QUALITY_ADMIN_EMAILS`（カンマ区切り）にメールを入れる。
  どちらも無ければ、診察用のアカウントでは403（画面に理由が出る）。
- 判定のモデルは `OPENAI_QUALITY_JUDGE_MODEL`（既定 gpt-4o）。変えたら `config.judge` に残るので、月の動きと切り分けられる。
