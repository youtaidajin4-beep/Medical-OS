# 文字起こし校正の精度を測る

「辞書を増やせば良くなるはず」で実装しないための道具です。**変更の前後で数字を比べ、
良くなったことを確かめてから入れる**ために使います。

## なぜ必要だったか

手で誤変換を考えて問題を作ると、直しやすい問題ばかりになります。実際、手で作った
12問では「辞書を全部渡す」が 11/12 まで上がりましたが、**本物の誤変換で測り直すと
その差は消えました**。手で作った「交信症→狭心症」のような素直な同音異義と、
音声認識が実際に出す「気持ちの障害→肝機能障害」「退場方針の寄与→帯状疱疹の既往」は
別物だからです。

## 使い方

```bash
cd apps/backend
export OPENAI_API_KEY=...

# 1. 問題を作る（初回のみ。作り直すと前の測定と比べられなくなる）
node eval/build-stt-corpus.mjs --rebuild

# 2. 条件を比べる（第1引数は試行回数）
node eval/run-correction-eval.mjs 5
```

`nest build` を先に走らせてください。`tsc` だけだと辞書のJSONが `dist` へ
コピーされず、**古い辞書で測ってしまいます**（実際に一度そうなりました）。

## 作りかた

1. `stt-corpus/scripts.json` … 読み上げる台本。内科の各領域をカバーする。**ここが正解**
2. macOS の `say` で読み上げ、本番と同じ文字起こし（gpt-4o-transcribe）にかける
3. 台本と食い違った文を集め、3つに分ける
   - **採点対象** … 辞書にある医療用語が失われた。校正で戻せるはず
   - **対照** … 数字・単位・かな漢字の書き方だけの違い（「五ミリグラム」→「5mg」）。
     これを変えたら改悪。正しい正規化を戻させてはいけない
   - **辞書の穴** … 本物の誤変換だが、その語が辞書に無くて的にできない。
     **足すべき語の一覧**として使う

行がまるごと一致するかでは採点しません。的は「失われた医療用語が戻ったか」だけです。
最初に行の一致で数えたときは、26件中6件が正しい正規化を誤って減点していました。

## 読みかた

- **回復率** … 失われた医療用語のうち、校正で戻った割合
- **改悪** … 変えてはいけない行を変えた数。0であるべき
- **幅** … 試行間のばらつき。条件の差が幅に収まっているなら、その差を根拠にしない

## これまでの測定（2026-09-21・的29件・対照11件・各5回）

| 条件 | 回復率 | 幅 | 改悪 |
|---|---|---|---|
| 辞書なし | 13% | 4pt | 0 |
| 各20語（当時の本番） | 14% | 0pt | 0 |
| **内科ぜんぶ（採用）** | **30%** | 4pt | 0 |

読みをヒントに足す案は**採用しませんでした**。同じ語数で読みを付けると
ヒントが2.4倍の長さになり、回復率が 11/12 → 9/12 に下がりました（別の測定）。
読みは索引の鍵として持ち、ヒントには出しません。

## 限界

- 合成音声です。実際の診察室の音（雑音・同時発話・小声・方言）とは違います。
  誤変換の傾向は本物ですが、頻度はそのまま当てはまりません
- 回復率は最良でも30%です。**校正で直せる誤変換はもともと多くありません。**
  「外相→咳嗽」のように音が遠いものは、語のリストでは戻せません。
  取りこぼしを減らす本筋は、文字にする前（音声認識へ語彙を渡す、音声を直接モデルへ入れる）にあります
- 谷口先生の実際の診察音声が手に入ったら、`scripts.json` ごと差し替えてください
