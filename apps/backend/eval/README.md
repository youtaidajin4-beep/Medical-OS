# 文字起こし校正の精度を測る

「辞書を増やせば良くなるはず」で実装しないための道具です。**変更の前後で数字を比べ、
良くなったことを確かめてから入れる**ために使います。

## なぜ必要だったか

手で誤変換を考えて問題を作ると、直しやすい問題ばかりになります。実際、手で作った
12問では「辞書を全部渡す」が 11/12 まで上がりましたが、**本物の誤変換で測り直すと
その差は消えました**。手で作った「交信症→狭心症」のような素直な同音異義と、
音声認識が実際に出す「気持ちの障害→肝機能障害」「退場方針の寄与→帯状疱疹の既往」は
別物だからです。

## 使い方

```bash
cd apps/backend
export OPENAI_API_KEY=...

# 1. 問題を作る（初回のみ。作り直すと前の測定と比べられなくなる）
node eval/build-stt-corpus.mjs --rebuild

# 2. 条件を比べる（第1引数は試行回数）
node eval/run-correction-eval.mjs 5
```

`nest build` を先に走らせてください。`tsc` だけだと辞書のJSONが `dist` へ
コピーされず、**古い辞書で測ってしまいます**（実際に一度そうなりました）。

## 作りかた

1. `stt-corpus/scripts.json` … 読み上げる台本。内科の各領域をカバーする。**ここが正解**
2. macOS の `say` で読み上げ、本番と同じ文字起こし（gpt-4o-transcribe）にかける
3. 台本と食い違った文を集め、3つに分ける
   - **採点対象** … 辞書にある医療用語が失われた。校正で戻せるはず
   - **対照** … 数字・単位・かな漢字の書き方だけの違い（「五ミリグラム」→「5mg」）。
     これを変えたら改悪。正しい正規化を戻させてはいけない
   - **辞書の穴** … 本物の誤変換だが、その語が辞書に無くて的にできない。
     **足すべき語の一覧**として使う

行がまるごと一致するかでは採点しません。的は「失われた医療用語が戻ったか」だけです。
最初に行の一致で数えたときは、26件中6件が正しい正規化を誤って減点していました。

## 読みかた

- **回復率** … 失われた医療用語のうち、校正で戻った割合
- **改悪** … 変えてはいけない行を変えた数。0であるべき
- **幅** … 試行間のばらつき。条件の差が幅に収まっているなら、その差を根拠にしない

## これまでの測定（2026-09-21・的29件・対照11件・各5回）

| 条件 | 回復率 | 幅 | 改悪 |
|---|---|---|---|
| 辞書なし | 13% | 4pt | 0 |
| 各20語（当時の本番） | 14% | 0pt | 0 |
| **内科ぜんぶ（採用）** | **30%** | 4pt | 0 |

読みをヒントに足す案は**採用しませんでした**。同じ語数で読みを付けると
ヒントが2.4倍の長さになり、回復率が 11/12 → 9/12 に下がりました（別の測定）。
読みは索引の鍵として持ち、ヒントには出しません。

## 限界

- 合成音声です。実際の診察室の音（雑音・同時発話・小声・方言）とは違います。
  誤変換の傾向は本物ですが、頻度はそのまま当てはまりません
- 回復率は最良でも30%です。**校正で直せる誤変換はもともと多くありません。**
  「外相→咳嗽」のように音が遠いものは、語のリストでは戻せません。
  取りこぼしを減らす本筋は、文字にする前（音声認識へ語彙を渡す、音声を直接モデルへ入れる）にあります
- 谷口先生の実際の診察音声が手に入ったら、`scripts.json` ごと差し替えてください

## SOAP転記の評価（`run-soap-coverage-eval.mjs`）

**何のための道具か。** 2026-09-29、谷口先生から「実用化するには zoom の文字起こし&要約くらいの
精度が最低でも必要」、翌9/30に「zoomの文字起こしもアプリと大差ない。文字起こしを要約に
持ってくる際の精度の違いなのでしょうか」。文字起こしが同等なら、**文字起こしを入力に固定して
要約以降だけを比べれば**、どこでどれだけ落ちているかがそのまま出る。それを測る。

```bash
OPENAI_API_KEY=... node eval/run-soap-coverage-eval.mjs 4
OPENAI_API_KEY=... node eval/run-soap-coverage-eval.mjs 4 --only after
EVAL_EXTRACT_MODEL=gpt-4o-mini OPENAI_API_KEY=... node eval/run-soap-coverage-eval.mjs 4 --only after
```

- **転記** … 会話に出てきた事実のうちSOAPに現れた割合。高いほど良い
- **捏造** … 言われていないのに書かれたもの（していない所見・測っていない値）。**0であるべき**
- 並ぶ条件は `before`（9/30時点の作り）、`after`（今の作り）、`zoom+gpt`（先生が
  Zoom要約をGPTでSOAPにしたもの。満足度50〜60%と評価されたもの）

`zoom+gpt` はAPIを呼ばずに採点できるので、鍵が無くても基準線だけは出る。
**この線を超えるまでは先生に「直りました」と言わない。**

的は `eval/soap-corpus/`（実診療なのでリポジトリには入っていない。中のREADME参照）。

### 2026-10-01 の実測（9/30の3症例・4試行）

| 条件 | 転記 | 捏造 | 1診察あたり |
|------|------|------|------------|
| before（9/30時点） | 27% | 1.0 | 約1.0円 |
| after（抽出 gpt-4o-mini） | 50〜55% | 0.0 | 約1.0円 |
| **after（抽出 gpt-4o・現行）** | **72〜73%** | **0.0** | 約2.0円 |
| zoom+gpt（先生の満足度50〜60%） | 74% | 0.0 | — |

症例別（現行）：① 倦怠感・関節痛・咳 66〜69%（zoom 65%）／② 著変なし・定時薬継続 **100%**（zoom 75%）／
③ 食生活の指導 72〜75%（zoom 100%）。先生の診療で一番多い②で上回っているのが実運用では効く。

試行ごとに数ポイント動く。**1〜2ポイントの差を根拠にしない。**

before の27%は、先生の体感「30〜50%くらい」(9/29) とほぼ一致している。
測り方が現実と合っていることの裏づけとして置いておく。

## 実診察に寄せた台本の通し測定（`eval/realistic/`、2026-10-16）

`scripts.py` の台本3本（初診15分・再診7分・再診5分）から、読み上げ用Markdown（`07_ROADMAP/15_realistic_scripts.md`）・再生用の合成音声・的を作る。
音声から通しで測る道具が3つ：

| 道具 | 通す経路 | 何のためか |
| --- | --- | --- |
| `run-e2e.mjs` | 録音全体の文字起こし（話者分離）→ SOAP | 補正を飛ばす簡易版。聞き違いが重く出る |
| `run-full.ts` | 録音全体（話者分離）→ 役割づけ → 辞書補正 → 知識層 → LLM校正 → SOAP | 診察中の文字が欠けたとき（従来経路）の本番と同じ |
| `run-live.ts` | 声の切れ目で区間に切る → 語彙ヒントつき文字起こし → 話者判別 → 補正 → SOAP | **実際のSOAPの材料になる経路**（診察中のリアルタイム） |

```bash
cd apps/backend && OPENAI_API_KEY=... npx ts-node eval/realistic/run-live.ts 3   # --retranscribe で文字起こしからやり直す
```

各道具は、薬名・病名・数字（台本の `TERMS`）が文字に残ったかも段ごとに数える。

### 2026-10-16 の測定（各3試行、合成音声。実際の声はもっと難しい）

| 条件 | 診察中の経路 | 録音全体の経路 |
| --- | --- | --- |
| 語の聞き取り（最終） | 36/38 | 29/38 |
| SOAP転記（変更前） | 87% | 88% |
| SOAP転記（「なし」の項目を残す指示を足した後） | **91%** | **91%** |
| 捏造 | 0 | 0 |

録音全体の経路は語彙ヒントを渡せない（話者分離モデルがpromptを受け付けない）ため、薬名・病名・数字の聞き違いが多い
（狭心症→強心症、15分→15秒、アムロジピン2.5ミリ→10ミリ）。数字・用量は危険側なので、画面の「要確認」で医師が確定する前提を崩さない。
