# SOAP転記の的（くしま内科・実診療）

この中身は**リポジトリに入れない**（`.gitignore` 済み）。実際の診療会話そのものだから。

手元に置くのは次の2つ:

- `cases.json` … 症例ごとの文字起こし・的・禁止パターン・比較対象のSOAP
- `transcripts.json` … 文字起こしだけを切り出したもの（cases.json を組み直すときの材料）

## どこから来たものか

2026-09-30、谷口先生が同じ日にアプリとZoomの両方を使い、その記録をLINEで送ってくださった。
- Zoomの文字起こし（3症例ぶん・名はイニシャル）
- ZoomのAI要約（症例ごと）
- Zoom要約をGPTでSOAP形式にしたもの（先生の満足度 50〜60%）

先生の見立ては「zoomの文字起こしもアプリと大差ない。文字起こしを要約に持ってくる際の
精度の違いなのでしょうか」。文字起こしが同等なら、文字起こしを入力に固定して要約以降だけを
比べれば、どちらがどれだけ落としているかがそのまま出る。この的はそのために作ってある。

## 新しい症例を足すとき

1. 文字起こしを `transcripts.json` に `{"症例ID": "本文"}` で足す
2. `cases.json` に的を書く。的は**文字起こしに実際に出てくる事実だけ**にする。
   音声認識で壊れて跡形もない事実（「肝機能」が「一般的な機能」になった等）は的にしない。
   ここで測りたいのは要約の段であって、音声認識の段ではないから
3. `accept` には言い換えを並べる（「関節痛」「間接」など、表記が違っても同じ事実なら当たり）
4. `forbidden` には、言われていないのに書かれたら事故になるものを正規表現で書く

## 合成の保留症例（cases-heldout.json）

2026-10-15。**調整に使っていない**、架空の会話3件（頭部MRI結果の説明／採血結果と下腿浮腫／ECG・心エコー結果と冠動脈CT予約）。
10/9に谷口先生から「S・Oに抜け（MRI結果・特記所見）」と指摘されたので、検査結果と特記所見を意図的に入れてある。
実患者のデータではないのでリポジトリに入れてよい。実診療の `cases.json` とは別ファイル。

```bash
EVAL_CORPUS=$PWD/eval/soap-corpus/cases-heldout.json OPENAI_API_KEY=... node eval/run-soap-coverage-eval.mjs 3 --only after
```

会話の文字は整っている（実際の音声認識の誤りは入っていない）。ここで測れるのは「要約の段が検査結果・特記所見を落とさないか」だけで、
聞き取りの段は `12_term_verification_script.md` で測る。
